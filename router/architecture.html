System Architecture

muLLM routes queries through a tiered pipeline — ground truth fast-path first, vector cache second, LLM routing last. Cloud tokens fire only when the local tier genuinely cannot handle it.

Pipeline
⌨️
Entry
User Query
POST /query ▼
  • Accepted via POST /query with JSON body {"content": "..."}
  • Source tag (api, chat, mcp, voice) controls routing hints
  • Request deduplication: identical queries within DEDUP_WINDOW_SECONDS return the cached result immediately
  • Rapid-fire protection: sessions limited to 20 requests/minute
  • Loop detection: same content hash 3+ times in 5 minutes triggers a warning
⚡
Fast Path
Ground Truth Resolver
~0.1 ms ▼
  • 200+ instant answers for dates, math, philosophy quotes, music theory, HTTP codes, ASCII art, and more
  • Identity resolver handles "who are you" / "what model" questions with zero LLM calls
  • try_resolve_locally() — pure Python pattern matching, no network I/O
  • Shortcircuits the entire pipeline on a match, returning cost $0.000000
  • Categories: dates/time math HTTP codes philosophy music
🗄️
Cache
Vector Similarity Cache
ChromaDB ▼
  • Embeds query with nomic-embed-text (Ollama), looks up nearest vectors in ChromaDB
  • Cosine similarity threshold: hits above 0.92 (configurable) are returned immediately
  • Cache misses continue down the pipeline; hits are returned with "source": "cache"
  • Async-aware: lookup_async() runs embedding in a thread pool to avoid blocking the event loop
  • Cache displacement Elo tracks which model's answers get displaced — passive model ranking with zero extra calls
🧠
Classify
Hybrid Intent Classifier
Ollama ▼
  • Layer 1 — Keyword rules: 80+ regex patterns, ~0.01 ms, handles 80%+ of queries without any LLM call
  • Layer 2 — LLM dual opinion: if rule confidence < CLASSIFIER_DUAL_THRESHOLD, a local Ollama model classifies as a second opinion
  • Categories: simple, code, note, vision, general, complex, creative, math
  • Returns an IntentObject with category, complexity score 1–5, and confidence
  • Semaphore-limited Ollama concurrency prevents VRAM saturation
⚖️
Route
Cost-Optimized Tier Selection
5 Tiers ▼
  • Tier 1 — Simple Local (complexity 1): instant local inference, free
  • Tier 2 — Local (complexity 2): full local Ollama model, free
  • Tier 3 — Local Multi (complexity 3): multi-step local reasoning, free
  • Tier 4 — Cloud Cheap (complexity 4): Haiku, GPT-4o-mini, Gemini Flash, lowest cloud cost
  • Tier 5 — Cloud Full (complexity 5): Sonnet, GPT-4o, Gemini Pro, full power
  • Daily budget cap ($5/day default) blocks over-spend; auto-approval ceiling controls user prompts
  • Spend velocity tracking: if costs accelerate, tier selection gets more conservative
Execution branches
💻
Tier 1–3
Local Ollama
$0.00 ▼
  • Runs qwen3.5:9b on RTX 5090 32GB via Ollama HTTP API
  • SSE streaming via GET /query/stream for real-time token delivery
  • Models pre-warmed on startup with a trivial prompt to load into VRAM
  • Keepalive loop pings every 30 min to prevent VRAM eviction
  • Separate models for general, code, classifier, and vision tasks
🔀
Split Route
Parallel Decomposition
Parallel ▼
  • POST /query/split — decomposes multi-part prompts into sub-tasks
  • Each sub-task is classified and routed independently to cheapest capable model
  • asyncio.gather() runs all sub-tasks in parallel, not sequential
  • Returns SplitResult with per-subtask tier, cost, and latency breakdown
  • Optimal for prompts like "explain X and also write Y and summarize Z"
☁️
Tier 4–5
Cloud APIs
Paid ▼
  • Anthropic (Claude Haiku, Sonnet), OpenAI (GPT-4o-mini, GPT-4o), Google (Gemini Flash, Pro)
  • Pricing config in config/settings.py — 12 cloud model variants with per-token costs
  • Model selection uses Elo-ranked leaderboard to prefer highest-performing at each price point
  • Async HTTP via httpx.AsyncClient, shared session with connection pooling
  • Fires only when local tier cannot handle complexity or user explicitly forces cloud
📊
Post-process
Score + Cache Back
JSONL log ▼
  • Response scored: latency, token count, cost, tier used, cache hit/miss
  • Result written to ChromaDB vector cache for future retrieval
  • Outcome appended to JSONL scoring log (cache/data/scoring_log.jsonl)
  • Session cost updated via add_session_cost(), live ticker emits via SSE
  • Cache displacement Elo updated if a new answer replaces an existing cached one
  • SSE event published to all dashboard subscribers for real-time updates
Clever Techniques
🔍
Vector Cache
cosine similarity · ChromaDB
▼

Queries are embedded with nomic-embed-text and stored as high-dimensional vectors in ChromaDB. On each new query, the embedding is computed and the top-k nearest neighbors are fetched by cosine similarity. If the closest match exceeds the 0.92 threshold, the stored answer is returned instantly — no LLM call.

  • Threshold tunable via CACHE_SIMILARITY_THRESHOLD env var
  • Async embedding via thread pool — never blocks FastAPI event loop
  • Cache grows passively; every answered query seeds future hits
  • ChromaDB persists to disk across restarts (cache/data/chromadb/)
🧬
Hybrid Classifier
keyword rules + LLM dual opinion
▼

Classification is a two-layer cascade. Layer 1 runs 80+ regex rules in ~0.01 ms and handles roughly 80% of queries — no LLM token burn. Only when confidence falls below CLASSIFIER_DUAL_THRESHOLD does Layer 2 fire an Ollama LLM as a second opinion.

  • Rules cover: notes, code, math, creative, general, complex, vision, retrieval
  • Each rule has a weight and minimum confidence to trigger Layer 2
  • Dual opinion aggregated by highest confidence wins
  • Semaphore limits Ollama calls — no VRAM saturation under bursty load
🏆
Cache Displacement Elo
passive model ranking
▼

Whenever a new answer displaces an existing cached one (the user ran the same query again and got a different model), the Elo rating of each model is updated. No explicit rating calls, no annotations — the act of displacement is the signal.

  • Winner: the model whose answer was chosen to replace the old one
  • Loser: the model whose answer was evicted from cache
  • Elo K-factor: 32 (standard competitive rating)
  • Leaderboard visible at GET /api/leaderboard
  • Tier selection uses Elo rankings to pick highest-rated model at each price tier
⚡
Ground Truth Resolver
200+ instant answers, 0 tokens
▼

A library of 200+ deterministic answers for queries where an LLM adds zero value. Pattern-matched in pure Python before the pipeline even starts — under 0.1 ms, zero network, zero cost.

  • Dates/time: "what day is it", "what year", "current time"
  • Math: arithmetic, powers, factorials via eval() sandbox
  • Philosophy quotes: Stoics, Socrates, Nietzsche, Kant
  • Music theory: chord names, intervals, scales
  • HTTP codes: 200, 404, 418, 500, 503 explained
  • Identity: "who are you", "what model" — always honest about being muLLM
🔀
Split Routing
decompose + parallel execution
▼

Multi-part prompts (e.g. "explain X, write code for Y, and summarize Z") are decomposed into independent sub-tasks, each routed to the cheapest model that can handle its complexity, then executed in parallel with asyncio.gather().

  • Decomposition via local LLM — one cheap classification call
  • Sub-tasks can mix tiers: simple sub-task = local free, complex = cloud cheap
  • Total cost = sum of sub-task costs, often cheaper than routing the whole thing cloud
  • Response recombined with section headers per sub-task
💰
Cost-Optimized Tier Selection
daily budget + velocity guard
▼

The router never fires cloud unless complexity demands it. Tier selection uses the intent complexity score (1–5), Elo rankings, daily budget remaining, and spend velocity to pick the cheapest capable model.

  • Daily hard cap: default $5/day, configurable via DAILY_BUDGET_CAP
  • Auto-approve ceiling: cloud calls below threshold proceed without confirmation
  • Ask-approval ceiling: calls above threshold prompt user in the Unblock panel
  • Spend velocity: if cost/minute spikes, tier ceiling lowers automatically
📡
Session Cost Ticker
live SSE · per-session tracking
▼

Every query result publishes a cost event to an SSE event bus. The chat UI receives real-time token counts and dollar amounts without polling. Session cost accumulates in memory and is queryable at any time.

  • GET /query/stream — SSE endpoint, each message includes cost field
  • GET /api/session/cost — current session total
  • Multiple dashboard subscribers each get their own asyncio.Queue
  • Queue overflow protection: put_nowait silently drops if subscriber is slow
