6. Security

Your keys are safe. They're stored in .env on your local machine only, never sent to muLLM's code or any third party. The .env file is automatically added to .gitignore and permissions are set to owner-only (600).

Ollama needs no API key — it runs entirely on your machine. Leave OLLAMA_API_KEY blank for local use.
Seal the .env file (advanced)
For maximum protection, make the config read-only then immutable. Once sealed, even root cannot modify it without explicitly removing the immutable flag. # Step 1: restrict to owner-read-only
chmod 0400 ~/.config/mullm/.env

# Step 2: make immutable (Linux — requires sudo)
sudo chattr +i ~/.config/mullm/.env WARNING: After chattr +i the file cannot be modified or deleted without removing the immutable flag first. muLLM reads but never writes to a sealed config.

Emergency recovery: sudo chattr -i ~/.config/mullm/.env # remove immutable flag
chmod 0600 ~/.config/mullm/.env # restore write access On macOS use sudo chflags schg ~/.config/mullm/.env and sudo chflags noschg to unseal.
Secret managers & env-from-vault (advanced)
If you prefer to keep plaintext keys out of .env entirely, muLLM supports loading values from an external secret manager at startup. Set values in .env using the SECRET: URI prefix and muLLM resolves them at startup — the plaintext never touches disk.

pass (Unix password store): ANTHROPIC_API_KEY=SECRET:pass:infra/openai_keys/anthropic
OPENAI_API_KEY=SECRET:pass:infra/openai_keys/openai File-based (org secret mount): ANTHROPIC_API_KEY=SECRET:file:/opt/secrets/mullm/anthropic_key Environment passthrough (CI / Docker): If a key is already in the process environment (e.g. injected by Kubernetes Secrets or Doppler), just leave it out of .env entirely — muLLM picks it up from the environment automatically.

Other supported backends: HashiCorp Vault, AWS SSM/Secrets Manager, GCP Secret Manager, Azure Key Vault, 1Password CLI (op), Doppler CLI — contact support or see router/secrets.py for the resolver interface.
TLS 1.3 + Post-Quantum (inbound HTTPS)
muLLM listens on HTTP by default for local use. For remote/team access, put it behind nginx or Caddy and get TLS 1.3 + HSTS for free:

Caddy (automatic HTTPS, simplest): mullm.your-domain.com {
  reverse_proxy 127.0.0.1:6856
  tls {
    protocols tls1.3
  }
} nginx + post-quantum (X25519MLKEM768 key exchange): ssl_protocols TLSv1.3;
ssl_ecdh_curve X25519MLKEM768:X25519;
ssl_stapling on;
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload"; All outbound calls to Anthropic/OpenAI/Google already use TLS 1.3 via Python's httpx with system OpenSSL. The post-quantum key exchange applies to inbound connections from browsers and other clients.

7. Remote Access Auth optional

muLLM supports Google OAuth2 / OIDC to protect the dashboard, setup, studio, bench, and debug pages when accessed from a non-localhost IP.

Localhost (127.0.0.1) and LAN (10.0.0.x) always bypass auth — no login required for local use.

To enable, set these three environment variables before starting the server:

GOOGLE_CLIENT_ID=<your-client-id>.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=<your-client-secret>
MULLM_BASE_URL=https://<your-public-host>:6856
Then add https://<your-public-host>:6856/auth/callback as an authorized redirect URI in your Google Cloud OAuth credentials.

Also install the auth dependencies:
pip install mullm[auth]

If GOOGLE_CLIENT_ID is not set, auth is completely disabled — no redirects, no 401s, everything works exactly as before.

8. IDE & Agent Integrations MCP · A2A · OpenAI-compat

muLLM works as a drop-in backend for tools you already use. Once installed it speaks three protocols:
  • MCP (Model Context Protocol) — native tool/resource server for Claude Code, Cursor, and any MCP-aware client
  • A2A (Agent-to-Agent) — Google's agent interop protocol; muLLM can act as an A2A agent or call other A2A agents
  • OpenAI-compatible API — /v1/chat/completions endpoint works with Aider, Continue, Codex, LLM CLI, and anything that accepts a custom base URL
Claude Code (MCP native)
Add muLLM as an MCP server so Claude Code can call it as a tool: # In ~/.claude/settings.json (or project .claude/settings.json)
{
  "mcpServers": {
    "mullm": {
      "command": "npx",
      "args": ["-y", "@0101/mullm-mcp"],
      "env": { "MULLM_URL": "http://127.0.0.1:6856" }
    }
  }
} Or via CLI: claude mcp add mullm -e MULLM_URL=http://127.0.0.1:6856 -- npx -y @0101/mullm-mcp

Full MCP documentation →
Continue.dev (OpenAI-compatible)
In your Continue config (~/.continue/config.json): {
  "models": [{
    "title": "muLLM (local-first)",
    "provider": "openai",
    "model": "mullm-auto",
    "apiBase": "http://127.0.0.1:6856/v1",
    "apiKey": "mullm"
  }]
}
Aider (OpenAI-compatible)
aider --openai-api-base http://127.0.0.1:6856/v1 --openai-api-key mullm --model mullm-auto

Or set in ~/.aider.conf.yml: openai-api-base: http://127.0.0.1:6856/v1
openai-api-key: mullm
model: mullm-auto
VSCode (via Continue extension)
Install the Continue extension from the VSCode Marketplace, then follow the Continue.dev config above. muLLM will route code completions and chat locally (free, no cloud) and escalate to cloud only for complex generation.
Antigravity / other OpenAI-compat tools
Any tool that accepts a custom OpenAI base URL works with muLLM:

Base URL: http://127.0.0.1:6856/v1
API Key: mullm (or any string — not validated for local use)
Model: mullm-auto (let muLLM choose) or any cloud model name

8.5. Run on Startup optional

Make muLLM start automatically when you log in. One command installs the right service for your OS:

mullm --install-service
▶ Manual setup — Linux / macOS / Windows

Creates a systemd user service — no root required. Runs after login, restarts on failure.

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/mullm.service <<'EOF'
[Unit]
Description=muLLM local LLM router (HTTPS :6856)
After=network.target

[Service]
Type=simple
WorkingDirectory=~/newdev/newestmullm
ExecStart=~/.venv/bin/python -m router.main
Restart=on-failure
RestartSec=5
Environment=PYTHONUNBUFFERED=1
Environment=MULLM_REMOTE_ACCESS=true
Environment=MULLM_SSL_CERTFILE=~/newdev/newestmullm/certs/server.crt
Environment=MULLM_SSL_KEYFILE=~/newdev/newestmullm/certs/server.key

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable mullm
systemctl --user start mullm

Creates a LaunchAgent plist — loads at login, restarts on crash.

mkdir -p ~/Library/LaunchAgents
cat > ~/Library/LaunchAgents/com.mullm.router.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.mullm.router</string>
  <key>ProgramArguments</key>
  <array>
    <string>/path/to/.venv/bin/python</string>
    <string>-m</string>
    <string>router.main</string>
  </array>
  <key>WorkingDirectory</key><string>/path/to/newestmullm</string>
  <key>EnvironmentVariables</key>
  <dict>
    <key>PYTHONUNBUFFERED</key><string>1</string>
    <key>MULLM_REMOTE_ACCESS</key><string>true</string>
  </dict>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
</dict>
</plist>
EOF
launchctl load -w ~/Library/LaunchAgents/com.mullm.router.plist

Two options: Task Scheduler (built-in) or NSSM (recommended for automatic restarts).

Option A — Task Scheduler:

# In PowerShell (run as Administrator)
$action = New-ScheduledTaskAction `
  -Execute "C:\path\to\.venv\Scripts\python.exe" `
  -Argument "-m router.main" `
  -WorkingDirectory "C:\path\to\newestmullm"
$trigger = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "mullm" `
  -Action $action -Trigger $trigger -RunLevel Highest

Option B — NSSM (recommended):

# Download: https://nssm.cc/download
nssm install mullm "C:\path\to\.venv\Scripts\python.exe" "-m" "router.main"
nssm set mullm AppDirectory "C:\path\to\newestmullm"
nssm set mullm AppEnvironmentExtra MULLM_REMOTE_ACCESS=true
nssm start mullm

8.8. Terrain & Map API Keys optional

The Terrain Builder (/terrain) works out of the box with procedural generation and USGS (free, CONUS). Add these keys to unlock global real-world DEM data.

OpenTopography — free, global 30m DEM (NASADEM, SRTM, Copernicus)
Cost: Free for non-commercial use. No rate limits for normal usage.
Sign up: portal.opentopography.org → My OpenTopo → Request API Key

Add to your systemd service (in ~/.config/systemd/user/mullm.service):
Environment=OPENTOPOGRAPHY_API_KEY=your_key_here Or set in your shell profile for the session: export OPENTOPOGRAPHY_API_KEY=your_key_here Covers: NASADEM (30m), SRTM GL1 (30m), SRTM GL3 (90m), Copernicus DEM (30m). Excellent for medium/large-scale terrain (~5km+).
Mapbox — global DEM tiles, higher resolution at city scale
Cost: Free tier: 50,000 tile loads/month (more than enough for dev). Pay only if you exceed that.
Sign up: account.mapbox.com → Create account → Access tokens → Create token

Add to your systemd service:
Environment=MAPBOX_TOKEN=pk.eyJ1... Resolution varies by zoom level: zoom 10 ≈ 100m/px, zoom 13 ≈ 10m/px. Best for city-scale or high-detail small areas.
After adding keys: restart muLLM (systemctl --user restart mullm.service) then reload the Terrain Builder — the data source status dots will turn green.
